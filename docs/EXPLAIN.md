# Explain it

## In one paragraph

This is a static portfolio site with a small evidence manifest, three selected project summaries, engineering principles, and a printable resume. The descriptions distinguish merged implementation from deployment status, limitations, and evidence provenance.

## The useful demo

1. Open the portfolio homepage.
2. Open a selected repository.
3. Read its README and tests.
4. Use the documented commands to reproduce its local checks.
5. For the merged Hybrid Log Classifier triage workflow, inspect [PR #5](https://github.com/HarshCodeK/hybrid-log-classifier/pull/5); it is advisory-only and does not execute remediation.

## If an interviewer asks

**Why no frontend framework?**  
The portfolio is a static site. A framework would not add meaningful value to the portfolio itself.

**How do you keep the site honest?**  
Project descriptions are reviewed against repository code and tests. Test counts are checked-in baseline snapshots, not live metrics.

**What does it cost to run?**  
The site is static and can be hosted as static files. The project repositories have their own runtime dependencies.

## What the site does not claim

It does not claim that the featured projects are production systems, that application-level controls equal OS isolation, or that portfolio test counts prove production reliability.
