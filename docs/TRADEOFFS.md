# Tradeoffs

## Portfolio-level choices

1. **Static site over a frontend framework** — the portfolio does not need application-state complexity.
2. **Checked-in evidence manifest over live repository scraping** — the site remains deterministic and has no runtime dependency on GitHub APIs.
3. **Three complementary projects over a long list** — the shortlist emphasizes reliability engineering, gateway controls, and deterministic business logic.
4. **Manual claim review over elaborate generation** — project descriptions are short enough to audit directly against repositories.
5. **Explicit limitations over inflated scope** — current behavior is separated from proposed PR changes.

## Deliberate refusals

- No invented production metrics or user counts.
- No claim that an application-level path boundary is OS isolation.
- No claim that a deterministic reconciliation core is a payment-execution system.
- No claim that KAY-KAY's provider stubs are live provider integrations.
- The incident-triage workflow is merged; no claim that it is deployed or production-ready.
